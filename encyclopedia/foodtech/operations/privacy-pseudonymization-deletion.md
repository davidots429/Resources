---
title: 개인정보 가명화와 삭제 수명주기
---

개인정보 보호 기능은 원문 식별정보를 일반 업무 데이터에서 격리하고, 업무에는 목적별 가명값을 사용하며, 보존기간 종료나 삭제 요청 때 원문·연결정보·파생본까지 추적해 삭제한다. 감사와 통계에 필요한 최소 정보는 재식별할 수 없는 형태로 분리한다.

사용자와 매장 활동을 모두 영구 식별자로 연결하면 편리하지만 유출과 오용의 영향이 커지고, 탈퇴 뒤에도 백업·캐시·임베딩에서 개인을 계속 복원할 수 있다. 단순히 화면의 사용자 행만 지워서는 암호화된 원문, 연결 키와 파생 데이터가 남을 수 있다.[^basis]

그래서 식별 원문, 기간별 연결정보와 업무 이벤트를 분리한다. 삭제는 한 레코드의 논리 삭제가 아니라 키 폐기와 파생 저장소 전파를 포함하는 수명주기로 관리한다.

## 보호 대상과 접근

- 개인정보와 기밀정보를 항목별로 분류한다.
- 원문 식별정보를 `identity_vault`에 격리한다.
- 업무 목적과 기간별 가명 연결을 `link_capsule`로 관리한다.
- 일반 업무·분석에는 승인된 가명 식별자만 제공한다.
- 외부 AI 전송 전에 개인정보와 비공개 정보를 탐지·차단한다.
- 삭제 대상이 저장소, 캐시, 큐, 임베딩과 데이터셋에 남아 있는지 추적한다.
- 삭제 실행과 검증 결과를 재식별 정보 없이 감사한다.

## 가명화 구조

원문 식별정보는 접근권한이 제한된 Vault에 보관한다. 업무 서비스는 원문 대신 목적이 정해진 HMAC 기반 가명값을 사용하고, 서로 다른 목적의 데이터가 불필요하게 결합되지 않도록 purpose와 기간을 분리한다.

기간별 연결이 필요하면 암호화된 capsule이 가명값과 Vault 위치를 연결한다. 이 방식을 택한 이유는 일반 업무 저장소가 원문을 알지 못하게 하면서도 승인된 권한과 목적 안에서는 필요한 연결을 수행하기 위해서다.

## 삭제 수명주기

1. 삭제 요청의 대상, 권한과 보존 예외를 확인한다.
2. Vault 원문, capsule과 암호화된 데이터 키의 위치를 식별한다.
3. 업무 저장소, 객체 저장소, 캐시, 검색색인, 큐와 임베딩의 파생 대상을 찾는다.
4. 허용된 대상은 Hard Delete하고 복호화 키를 폐기해 crypto-shred를 수행한다.
5. 백업 복원 때 삭제된 정보가 되살아나지 않도록 삭제목록을 다시 적용한다.
6. 삭제 범위와 결과를 개인을 다시 식별할 수 없는 receipt로 기록한다.

개인정보 삭제는 모델과 데이터셋의 완전한 과거 재현보다 우선한다. 삭제 대상이 학습에 사용됐다면 원천 키 삭제만으로 모델 영향이 사라졌다고 보지 않고, 해당 모델·데이터셋을 오염 가능 상태로 표시해 사용중단, 재학습 또는 검증된 제거방법을 적용한다.

## 외부 전송과 보존

외부 AI에는 원문 ID, 위치, 접속정보와 불필요한 영업정보를 보내지 않는다. 공개자료, Mock과 합성 데이터가 아닌 정보는 데이터 분류와 공급자 정책을 통과해야 한다. 로컬 Ollama 처리와 외부 API 전송은 별도로 표시한다.

Golden Dataset은 승인된 제거와 검수를 통과한 데이터만 사용한다. 데이터셋 manifest, 스키마·코드·모델·프롬프트 버전과 평가결과는 재식별 연결 없이 보존할 수 있다.

## 실패와 책임 경계

- 가명화는 익명화와 같지 않다. 연결 capsule과 키가 남아 있으면 승인된 조건에서 재연결될 수 있다.
- 암호화만으로 보존기간과 삭제 의무가 없어지지 않는다.
- 감사·법적 보존 예외가 있더라도 업무 화면에서 원문을 계속 노출하는 근거가 되지 않는다.
- HMAC purpose, canonical encoding, 키 계층과 capsule API 권한은 최종 확정 전이다.
- 국외 이전 고지·동의·철회와 공급자별 보존정책은 공개 데모·운영 준비 전에 법률 검토와 함께 확정한다.
- 백업의 KMS 삭제 대기와 WORM 보존이 즉시 삭제 요구와 충돌하는 경우의 절차는 운영정책에서 정한다.

## 설계 상태와 남은 작업

원문 Vault 격리, 목적·기간별 가명 연결, crypto-shred와 파생 저장소 삭제 전파 원칙은 설계에 반영됐다. 키 계층, DynamoDB 키·인덱스, 삭제 receipt, 국외 이전과 운영 절차는 관련 체크포인트에서 확정한다.
