문제 해결 기록은 현상을 재현한 조건과 확인한 원인을 남기는 공간이다. 단순한 오류 목록으로 만들면 다음 사람이 같은 조사부터 반복하게 된다. 실제로 겪은 문제만 기록하고, 해결되지 않은 것은 그 상태와 다음 검증 조건을 밝힌다.

## 로컬 사이트에서 Foodtech 페이지가 404로 열릴 때

증상은 개발 서버에서 `/Resources/` 진입점은 열리는데 `/foodtech/`로 이동하면 404가 나는 것이다. GitHub Pages용 `base`가 `/Resources`로 설정되어 있으므로 프로젝트 페이지의 완전한 경로는 `/Resources/foodtech/`다. `astro.config.mjs`의 base를 임시로 `/`로 바꾸면 로컬 화면만 맞고 배포 링크가 어긋난다. 주소의 접두 경로와 생성된 링크를 확인한 뒤 `npm run build`로 동일한 경로가 생성되는지 검증한다.[^site]

## XLSX를 PDF로 바꿀 때 표가 쪼개질 때

여러 시트의 가로로 긴 표를 PDF로 강제하면 열이 여러 페이지로 나뉘거나 아주 작게 축소된다. 이 프로젝트에서는 DCD와 표 중심 산출물에 시트 전환·가로 스크롤이 있는 웹 뷰어를 사용한다. 원본 XLSX 다운로드도 제공해 셀·수식을 직접 확인할 수 있게 한다. PDF가 필요한 새 문서는 변환 결과의 모든 시트와 페이지를 확인한 뒤에만 공개한다.[^site]

## 설계 값이 실제 구현과 다를 때

2026년 10월 23일의 로컬 계약 점검은 일부 불변 조건만 확인했다. 저장소 키, 동시성, AWS 권한, 실제 장비 프로토콜은 이후 환경에서 재검증해야 한다. 설계값을 그대로 구현해 실패하면 재현 입력, 기대한 계약, 실제 결과, 원본 문서 버전과 수정 결정의 위치를 기록한다. 확정되지 않은 수치를 조용히 새 기본값으로 바꾸지 않는다.[^sad]

새 문제를 추가할 때는 날짜, 영향받은 버전·환경, 재현 절차, 원인으로 확인한 증거, 수정 내용, 재검증 명령, 아직 남은 위험을 적는다. 사용자 데이터나 키는 예시에 포함하지 않는다.

[^site]: [Resources 사이트 설정](https://github.com/davidots429/Resources/blob/main/astro.config.mjs), base·뷰어 구성.
[^sad]: [SAD v0.3](/Resources/foodtech/files/Foodtech_AI_Recipe_Agent_SAD_v0.3.docx), 검증 게이트와 미결정 인터페이스.
