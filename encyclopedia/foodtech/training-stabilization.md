## 한눈에 보기

교육과 안정화 지원은 사용자, 관리자, 개발자, 데이터 연계 담당자와 장애대응 담당자가 자신의 역할에 필요한 설치, 실행, 운영과 대표 절차를 재현할 수 있도록 문서와 교육을 제공하는 기능이다.

## 왜 이렇게 정했는가

기능이 완성되어도 특정 개발자만 설치·운영할 수 있으면 안정적인 서비스로 볼 수 없다. 사용자와 운영자에게 필요한 정보는 서로 다르고, 비밀값이나 보안 운영정보를 모든 사람에게 공개해서도 안 된다.

그래서 역할별 문서를 분리하고 기준 시스템 버전과 함께 관리한다. 문서만으로 대표 절차를 재현해 보는 이유는 실제 동작과 설명이 어긋나는 문제를 조기에 찾기 위해서다.

## 무엇을 하는가

- 사용자에게 화면과 업무 흐름을 안내한다.
- 관리자에게 계정, 권한, 모니터링과 복구 절차를 제공한다.
- 개발자에게 설치, 실행, 구성과 배포 절차를 제공한다.
- 연계 담당자에게 장비 프로파일과 데이터 계약을 설명한다.
- 장애대응 담당자에게 진단, 알림과 복원 절차를 제공한다.
- 교육 수행과 안정화 조치 결과를 기록한다.

## 어떻게 동작하는가

1. 기준 릴리스와 역할별 책임을 확인한다.
2. 역할마다 필요한 절차와 예제를 작성한다.
3. 비밀값과 제한된 보안정보를 일반 문서에서 분리한다.
4. 신규 환경에서 문서만으로 대표 절차를 실행한다.
5. 불일치가 있으면 문서 또는 기능 결함으로 기록한다.
6. [현장실증과 사용자 검증](field-validation.md)의 의견을 반영해 안정화한다.

## 예외와 경계

- 실제 비밀번호, API 키와 인증서 값을 예제로 넣지 않는다.
- 문서와 시스템 버전이 다르면 최신 절차로 간주하지 않는다.
- 교육 완료를 기능 검증이나 현장실증 통과로 대신하지 않는다.
- 비밀값과 보안 운영정보는 제한된 역할에만 제공한다.
- 테스트 결과와 결함 증적은 별도 테스트 산출물에서 관리한다.

## 현재 결정

사용자, 관리자, 개발자, 데이터 연계와 장애대응 문서를 역할별로 제공한다. 소스코드, 빌드·배포자료와 운영문서는 시스템 버전에 맞춰 함께 관리한다.

교육 방식, 수료 기준, 안정화 기간과 지원 범위는 대표 실증 시나리오와 배포 설계가 확정된 뒤 구체화한다.

## 최신 설계 반영

운영 문서는 개발표준의 오류 분류, 로그 필드, 재시도·DLQ, migration과 복구 runbook을 기준으로 작성한다. 릴리스 태그와 산출물 버전을 연결하고 데이터베이스·매핑·프롬프트·모델 버전을 독립 추적한다. 교육 완료는 화면·권한·장애복귀 절차를 실제 역할별로 확인한 뒤 기록한다.
