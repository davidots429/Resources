---
title: 데이터 품질 검토와 비파괴 재처리
---

품질 검토는 자동 품질판정의 사유를 사람이 확인하고, 확인·기각 또는 재처리를 요청하는 기능이다. 검토자가 원 판정을 직접 고쳐 정상으로 만들지 않으며, 모든 조치와 재처리 결과를 추가 이력과 새 파생 버전으로 남긴다.

자동 규칙은 미해석 코드나 통계적 이상을 잘못 경고할 수 있지만, 사람이 화면에서 상태만 `정상`으로 바꾸면 최초 판정과 판단 근거가 사라진다. 반대로 모든 이상을 격리하면 실제로 사용할 수 있는 데이터까지 업무와 분석에서 제외된다.[^basis]

그래서 종합 품질상태와 복수의 발견 사유를 분리하고, 검토결과는 단방향 이력으로 추가한다. 수정이 필요하면 원본과 최초 결과를 보존한 채 새 규칙 버전으로 재처리한다.

## Finding과 검토 대상

- 이벤트별 종합 품질상태와 여러 발견 사유를 보여준다.
- 적용 규칙, 버전, 원천 참조와 판정 제한을 확인한다.
- 경고를 확인하거나 오탐으로 기각한다.
- 격리 데이터의 재처리를 요청한다.
- 재처리의 부모·자식 버전과 결과를 추적한다.
- 작업자, 시각, 사유와 처리 결과를 추가 이력으로 보존한다.

## 품질상태와 검토상태

| 자동 품질상태 | 초기 검토상태 | 허용되는 주요 조치 |
| --- | --- | --- |
| `VALID` | `NOT_REQUIRED` | 일반적으로 별도 검토하지 않음 |
| `WARNING` | `PENDING` | `CONFIRMED` 또는 `DISMISSED` |
| `QUARANTINED` | `PENDING` | `CONFIRMED` 또는 `REPROCESS_REQUESTED` |

`DISMISSED`는 경고 사유가 업무상 문제가 아님을 기록하는 검토결과다. 원본 자동판정을 삭제하는 동작이 아니다. 격리된 데이터는 단순 기각으로 정상화하지 않고, 규칙·매핑·문맥을 보완한 뒤 재처리한다.

## 새 시도로 재처리하는 과정

1. 자동 판정이 `data_quality_assessment`에 종합 상태를 기록한다.
2. 각 사유는 `data_quality_finding`에 독립적으로 기록한다.
3. `SCR-210` 품질 검토 화면이 대기 중인 경고와 격리 항목을 보여준다.
4. 검토자가 사유와 원천 참조를 확인하고 허용된 조치를 선택한다.
5. 조치는 `quality_review_history`에 추가되며 기존 이력은 수정·삭제하지 않는다.
6. 재처리 요청은 부모 버전을 참조하는 새 파생 버전을 만들고 다시 품질을 판정한다.

상태 변경과 이력 추가는 같은 트랜잭션으로 처리한다. 이 원칙을 두는 이유는 화면의 현재상태와 감사이력이 서로 다른 결과를 가리키는 일을 막기 위해서다.

## 재처리 경계

- Ingestion 단계에서 구조 자체를 해석할 수 없는 데이터는 원시 DLQ에 둔다.
- 이벤트 봉투가 만들어진 뒤 표준화에 실패한 데이터는 표준화 DLQ에 둔다.
- 결정적인 단위·형식 변환은 규칙 버전과 전후 값을 보존한 경우에만 자동 적용한다.
- 결측치 추정, 보간과 모델 기반 대치는 원본 자동 보정으로 취급하지 않는다.
- 늦게 도착한 데이터는 `LATE_AFTER_GAP`을 남기고 필요한 범위만 새 버전으로 계산한다.

## 실패와 책임 경계

- 검토자는 `VALID` 상태를 임의로 만들 수 없다.
- `QUARANTINED` 데이터는 재처리 전 정상 분석과 학습에 사용하지 않는다.
- 경고 이력이 있는 데이터의 학습 적격성은 별도 규칙으로 판단한다.
- DLQ 보존기간, 운영 승인 역할과 재처리 절차는 공개 데모·운영 준비 전에 확정한다.
- 중복 해시 정규화, 재처리 멱등성과 파생 재계산 범위는 기술검증이 필요하다.

## 설계 상태와 남은 작업

종합 상태와 복수 사유의 분리, 단방향 검토상태, 추가 전용 이력과 새 파생 버전 방식은 현재 설계 기준이다. 해시·멱등성, DLQ 운영값과 재계산 범위는 각각 기술검증과 운영 준비 단계에서 확정한다.
