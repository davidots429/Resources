---
title: Mock 오류 시나리오와 검증
---

Mock 오류 시나리오는 연결 단절, 중복, 결손, 지연 도착, 인증·인코딩·스키마 오류와 센서 이상을 의도적으로 만들어 수집·표준화·품질·복구 흐름을 검증한다. 같은 시드와 시나리오 버전을 사용하면 사건 순서와 기대 결과를 다시 만들 수 있어야 한다.

정상 데이터만 생성하면 시스템이 가장 중요한 실패 경계에서 어떻게 동작하는지 알 수 없다. 그러나 오류값을 정상 스키마에 섞어 넣거나 매번 무작위로 만들면 무엇을 검증했는지 재현하기 어렵다.[^basis]

그래서 정상 스키마는 그대로 유지하고 오류 종류, 발생시점, 지속시간과 기대 결과를 별도 시나리오로 정의한다. 결정적 시드는 동일한 입력이 동일한 오류와 판정을 만들게 하며, 수정 전후 회귀시험을 가능하게 한다.

## 오류 시나리오 범위

| 범주 | 대표 시나리오 | 기대 처리 |
| --- | --- | --- |
| 연결 | 단절, 재연결, timeout | 연결상태와 지연·상실 사유 기록 |
| 전달 | 중복, 순서 뒤바뀜, 결손, 늦은 도착 | 순서 복원, 멱등 처리, `DATA_GAP`, 새 파생 버전 |
| 인증·통신 | 인증 실패, TLS·프로토콜 오류 | 수집 거부와 오류상태, 비밀정보 없는 로그 |
| 형식 | JSON·XML·CSV 구조 오류, 인코딩 오류 | 원시 또는 표준화 DLQ로 분리 |
| 의미 | 미지 코드, 미지원 필드, 단위 불일치 | 원천값 보존, `UNMAPPED` 또는 가용성 상태 |
| 센서 | 급변, 고정값, 물리 한계, 상호 불일치 | 후보와 확정 이상 분리, 품질 finding 기록 |
| 업무 | 허용되지 않은 상태 전이, 완료 미기록 | 상태변경 거부와 시도 이력 |

## 오류 주입과 관찰

1. 기준 프로파일, fixture, 시드와 시나리오 버전을 선택한다.
2. 정상 이벤트 흐름을 만든 뒤 지정한 시점에 하나 이상의 오류를 주입한다.
3. Adapter 전 원천 스키마 검증과 변환 후 표준 스키마 검증을 각각 수행한다.
4. 수집 봉투, 순서 복원, 매핑, 품질 finding과 DLQ 결과를 기록한다.
5. 재연결·재전송·재처리 뒤 기대 상태와 파생 버전을 확인한다.
6. 같은 시드로 다시 실행해 사건 순서, 핵심 값과 판정이 일치하는지 비교한다.

## 결손과 늦은 도착

순번이 비면 5초 동안 복원을 기다린다. 그 안에 도착하면 순서를 복원하고, 지나면 `DATA_GAP`을 방출한다. 5초 수집주기에서 30초 연속 결손, 즉 6회 연속 수집 실패가 이어지면 `SENSOR_LOST`와 `DISCONNECTED`를 확정한다.

결손 확정 뒤 도착한 이벤트는 이전 결과에 삽입하지 않는다. `LATE_AFTER_GAP` finding과 부모를 가진 새 파생 버전을 만들고 필요한 범위만 다시 계산한다.

## 중복과 격리

동일 업무키와 동일 payload는 멱등 처리한다. 같은 키인데 payload가 다르면 데이터를 숨기지 않고 충돌 finding을 남긴다. 네트워크 재시도의 메시지 중복과 원천 장비가 실제로 중복 전송한 사건도 구분한다.

Ingestion 단계에서 스키마를 해석할 수 없으면 원시 DLQ로 보내고, 이벤트 봉투 생성 뒤 매핑·표준화에 실패하면 표준화 DLQ로 보낸다. 정상 스키마를 오류 샘플에 맞춰 넓히지 않는 이유는 운영 입력의 계약을 약화시키지 않기 위해서다.

## 센서와 업무 오류

센서 급변은 즉시 고장으로 확정하지 않는다. 보조센서·제어값 불일치, 오류코드, 물리 한계와 반복 패턴 같은 2차 근거를 확인해 `SUSPECTED`와 `CONFIRMED`를 나눈다. 후보값은 원천과 함께 보존하며, 확정된 이상만 품질정책에 따라 격리한다.

허용되지 않은 조리작업 상태 전이는 상태를 바꾸지 않고 시도와 사유를 기록한다. 완료시각, 안전평가나 품질평가가 빠진 경우도 작업 실패와 섞지 않고 완료 미기록 또는 평가 미완료로 표시한다.

## 실패와 책임 경계

- 오류 시나리오는 정상 제조사 동작을 주장하는 자료가 아니다.
- 자동 보정은 역산 가능한 결정적 변환에만 허용한다.
- 오류 때문에 원천 payload와 최초 품질판정을 수정하지 않는다.
- 구체적인 테스트 절차, 반복 횟수와 합격 증적은 테스트 산출물에서 관리한다.
- 중복 해시 canonicalization, 소스별 `STALE`·`OFFLINE` 임계치와 DLQ 보존기간은 아직 확정되지 않았다.
- 인증서, endpoint, topic, session과 retry 세부값은 프로토콜 기술검증 뒤 확정한다.

## 설계 상태와 남은 작업

재연결, 중복, 인증·인코딩 오류, 5초 결손 버퍼, 30초 연결 상실, 이중 DLQ, 늦은 도착의 새 파생 버전과 비파괴 재처리 원칙은 현재 기준이다. 실행 fixture의 정확한 payload, 해시·멱등성 세부 구현과 운영 임계치는 후속 기술검증·테스트·운영 준비 단계에서 확정한다.
