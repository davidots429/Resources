## 한눈에 보기

감사이력과 데이터 보호는 로그인, 레시피 변경·승인, 데이터 조회·등록·반출과 관리자 설정 변경을 추적하고, 인증정보·개인정보·매장 데이터와 외부 AI 전송 데이터를 보호하는 기능이다.

## 왜 이렇게 정했는가

중요한 변경의 주체와 결과를 알 수 없으면 사고와 오류를 조사하기 어렵다. 또한 이 프로젝트는 사용자, 매장 운영과 평가 데이터를 다루며 외부 AI 서비스도 사용하므로 화면, 로그, 백업과 외부 전송 전체에서 보호 기준이 필요하다.

그래서 중요 이벤트는 일반 사용자가 수정할 수 없는 감사이력으로 남기고, 비밀값과 개인정보는 필요한 범위에서만 수집·표시한다. 외부 AI 전송은 데이터 분류와 승인 상태를 먼저 확인한다.

## 무엇을 하는가

- 로그인 성공·실패와 접근 거부를 기록한다.
- 레시피 변경·승인·폐기와 관리자 설정 변경을 기록한다.
- 데이터 조회·등록·다운로드·반출을 추적한다.
- 비밀번호, API 키와 인증서를 안전하게 저장한다.
- 통신 구간에 암호화를 적용한다.
- 개인정보와 민감정보를 분류하고 마스킹한다.
- 외부 AI로 보낼 필드를 최소화하고 승인되지 않은 전송을 차단한다.

## 어떻게 동작하는가

1. 중요 작업이 시작되면 사용자, 역할, 대상과 요청 식별자를 확인한다.
2. 작업 결과와 필요한 변경정보를 감사이력에 기록한다.
3. 조회 시 역할과 매장 범위를 적용한다.
4. 비밀값은 보안 저장소나 암호화 저장을 사용하고 로그에 원문을 남기지 않는다.
5. 외부 AI 요청 전에 데이터 분류와 허용 필드를 확인한다.
6. 보존기간이 지난 정보는 승인된 파기 또는 익명화 절차로 처리한다.

## 예외와 경계

- 평문 비밀번호, API 키와 인증서 값을 문서나 로그에 기록하지 않는다.
- 클라이언트가 보낸 매장 범위만 신뢰하지 않는다.
- 승인되지 않은 개인정보와 영업정보를 외부 AI로 보내지 않는다.
- 감사이력 기록 실패 시 중요 변경을 계속할지에 대한 정책은 아직 확정되지 않았다.
- 개인정보의 구체적인 분류와 보존기간이 정해지기 전에는 임의로 장기 보존하지 않는다.

## 현재 결정

Free Tier AI에는 공개자료, Mock과 합성 데이터만 전송한다. 개인정보, 인증정보, 고객 고유 레시피와 비공개 영업정보가 포함된 운영 데이터는 최소화·비식별화한 뒤에도 Paid Tier만 사용한다.

개인정보 항목별 분류, 마스킹, 원문 접근권한, 보존·파기와 외부 전송 허용 범위는 설계 단계에서 확정한다. 감사로그 보존기간도 [백업과 복구](backup-recovery.md)의 데이터 보존정책과 함께 결정한다.
