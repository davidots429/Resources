title: 구조화된 레시피 생성
---

## 한눈에 보기

구조화된 레시피 생성은 메뉴명과 자연어 조리 요구를 재료, 투입량, 단계, 장비, 권장 조리조건, 품질 기준과 주의사항이 포함된 레시피 초안으로 바꾸는 기능이다. AI가 만든 결과는 바로 제공하지 않고 검토 전 상태로 저장한다.

## 왜 이렇게 정했는가

자유로운 문장만 생성하면 단계 누락과 단위 불일치를 자동으로 확인하기 어렵고, 이후의 승인·비교·분석 기능에서도 사용하기 어렵다. 그래서 AI 응답을 정해진 JSON 구조로 제한하고 애플리케이션에서 다시 검증한다.

AI는 현장 안전과 품질을 대신 책임질 수 없으므로 초안을 만드는 역할만 맡는다. 승인 권한을 가진 사람이 검토한 뒤에만 현장에 제공하며, 장비 제어 명령은 생성하거나 전송하지 않는다.

## 무엇을 하는가

- 메뉴, 제공량, 식재료, 선호, 제약과 운영조건을 입력받는다.
- 보유 장비와 장비별 제한사항을 함께 확인한다.
- 일관된 필드를 가진 레시피 초안을 생성한다.
- 출력 구조와 필수값을 검증한다.
- 사용한 모델, 프롬프트와 출력 스키마 버전을 내부적으로 연결한다.
- 실패한 결과를 승인된 레시피처럼 표시하지 않는다.

## 어떻게 동작하는가

1. 사용자가 메뉴와 필요한 조건을 입력한다.
2. 시스템이 필수정보와 사용자 권한을 확인한다.
3. 매장·장비·재료 조건을 조회해 AI 요청에 포함할 정보를 최소화한다.
4. AI가 구조화된 JSON 초안을 생성한다.
5. 애플리케이션이 스키마와 장비 제약을 검증한다.
6. 유효한 결과를 검토 전 레시피로 저장하고 [레시피 승인과 버전 관리](recipe-lifecycle.md)로 전달한다.

## 예외와 경계

- 필수정보가 없으면 추정으로 완성하지 않고 추가 입력을 요청한다.
- 구조 검증에 실패하면 최대 두 차례 보정 재시도를 수행한다.
- 최종 실패 시 AI 결과처럼 보이는 임의 기본값을 만들지 않는다.
- 개인정보, 인증정보와 승인되지 않은 비공개 운영정보를 외부 AI로 보내지 않는다.
- 생성 결과를 장비에 자동 전송하거나 자동 적용하지 않는다.

## 현재 결정

고급 추론에는 Gemini 3.1 Pro Preview를 사용하고, 개발은 `v1beta`, 운영은 `v1` API 경로를 사용한다. 응답은 JSON MIME type과 response schema로 제한하고 수신 후 다시 검증한다. 고급 추론 요청의 timeout은 60초다.

Preview 모델의 종료나 변경에 대비한 대체 모델, 기능별 안전 기본값과 세부 재시도 간격은 설계 단계에서 확정한다. 모델 교체 시에는 조리 도메인 평가 데이터로 회귀시험을 수행한다.
