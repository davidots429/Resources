## 한눈에 보기

AI 관리 기능은 로컬·외부 모델의 등록과 선택, 기능별 허용 등급, API 자격증명 보호, 비동기 작업, 사용량과 비용 한도를 함께 관리한다. 모든 LLM 호출은 AI Gateway를 통과하며, 고급 추론 작업을 한도 초과만으로 낮은 등급 모델에 자동 전환하지 않는다.

## 왜 이렇게 정했는가

모델 공급자마다 인증, 비용, 속도, 구조화 출력과 데이터 처리 조건이 다르다. 호출 코드를 기능마다 직접 구현하면 자격증명이 여러 서비스에 퍼지고, 모델이 변경될 때 품질과 비용 정책도 일관되게 적용하기 어렵다.

그래서 모델 정보와 자격증명을 업무 데이터에서 분리하고 전용 Gateway에서 정책을 검사한다. 모델 등급은 공급자의 마케팅 순위가 아니라 프로젝트 기능에 필요한 추론 수준과 fallback 허용 여부를 나타낸다.

## 무엇을 하는가

- Ollama, OpenAI, Google과 Anthropic 모델을 레지스트리에 등록한다.
- 공급자 표시명과 실제 호출 모델 ID를 분리한다.
- 기능별 허용 Tier, 공급자 상태, 한도와 외부 전송 정책을 검사한다.
- 사용자가 입력한 외부 API 키를 암호화해 저장한다.
- 비동기 AI 작업의 시도, 재시도, 만료와 결과를 추적한다.
- 호출량, 토큰, 지연, 오류, fallback과 추정 비용을 기록한다.
- 프롬프트·모델·출력 스키마 버전을 결과에 연결한다.

## 모델 선택과 fallback

기본 모델은 로컬 Ollama의 `llama3.1:8b`다. 기능은 프로젝트 Tier에 따라 모델을 선택한다.

- Tier 1은 복합 센서 분석과 레시피 보정 같은 고급 추론에 사용한다.
- Tier 2는 일반 대화와 일반 처리에 사용한다.
- Tier 3은 단순 요약과 저지연 응답에 사용한다.

일반 작업은 한도 초과나 일시 장애 때 허용된 기본 로컬 모델로 전환할 수 있다. Tier 1 작업은 자동으로 낮은 Tier로 내리지 않는다. 사용자는 `대기열에 저장`하거나 품질 저하 가능성, 선택 모델, 전송 위치와 예상 비용을 확인한 뒤 `로컬/저지연 모델로 새로 실행`할 수 있다. 이는 자동 fallback이 아니라 별도의 사용자 승인 실행으로 기록한다.

## 자격증명 등록과 사용

1. 사용자는 별도의 입력 화면에서 외부 공급자 API 키를 입력한다.
2. 키는 HTTPS 요청 본문으로 전송하며 URL, 쿠키와 일반 로그에 넣지 않는다.
3. 등록 서비스는 키를 저장용 Envelope Encryption으로 암호화하지만 저장된 키를 다시 복호화할 권한은 갖지 않는다.
4. 저장소에는 자격증명 암호문, 암호화된 데이터 키와 비민감 메타데이터만 둔다.
5. AI Gateway가 실제 호출 순간에만 복호화하고 호출이 끝나면 평문 참조를 제거한다.
6. 화면에는 원문 키를 다시 반환하지 않고 공급자, 상태와 등록·수정 시각만 보여준다.

브라우저 추가 암호화와 메모리 제거는 평문 노출 시간을 줄이는 통제다. 브라우저 확장이나 단말 침해까지 막는 절대적인 보장으로 표현하지 않는다.

## 비동기 작업과 사용량

AI 작업은 `ENQUEUED → PROCESSING → COMPLETED/FAILED/EXPIRED_RETRY_REQUIRED` 상태로 관리한다. SQS에는 작업 식별자와 만료정보만 두고, 암호화된 본문은 DynamoDB Claim Check 레코드에 단기 보관한다. 최초 시도와 최대 2회 재시도 뒤에도 처리되지 않으면 최소 메타데이터만 DLQ로 이동한다.

외부 유료 AI의 신규 계정 월간 안전 상한 기본값은 미화 10달러다. 로컬 Ollama 호출은 외부 API 비용 0달러로 집계하지만 전력·하드웨어 비용과 구분한다. 호출 전에는 예상비용으로 한도를 확인하고 호출 후 실제 사용량으로 보정한다.

## 예외와 경계

- 일반 서비스, 관리자와 프론트엔드는 저장용 KMS 복호화 권한을 갖지 않는다.
- 프롬프트 원문, API 키와 개인정보를 비용 로그나 SQS 메시지에 기록하지 않는다.
- 개인정보·비공개 레시피·영업정보의 외부 전송은 별도 데이터 정책을 통과한 경우에만 허용한다.
- 커스텀 모델은 Tier를 명시하고 회귀시험을 통과하기 전 고급 추론 작업에 사용하지 않는다.
- 모델 지원 종료 신호는 자동 교체 승인이 아니다. 후보 등록과 Golden Dataset 회귀시험이 필요하다.
- 라이브러리 버전, Gateway 내부 인증, KMS 세부 알고리즘과 실행 튜닝값은 기술검증·부하시험 뒤 확정한다.

## 현재 결정

다중 공급자 모델 레지스트리, Ollama 기본 모델, 기능별 Tier, AI Gateway 단독 복호화, Claim Check와 사용자 승인 fallback 원칙은 현재 기준이다. 세부 레지스트리 상태, 암호 구현체, 어댑터 호환성과 모델별 품질·성능 기준은 후속 설계·기술검증·시험에서 확정한다.
