---
title: 현장실증과 사용자 검증
---

현장실증은 대표 메뉴를 대상으로 데이터 수집, 표준화, AI 추천, 사람의 검토, 조리, 결과수집과 평가까지 전체 흐름을 실행하고 사용자 의견과 문제를 기록하는 기능이다. 실제 장비가 없는 현재 프로젝트에서는 Mock과 대체 입력을 포함한 검증으로 구성한다.

각 기능을 따로 시험해도 전체 흐름에서 식별자, 권한, 버전과 데이터가 제대로 이어지는지는 알 수 없다. 또한 사용자가 화면과 절차를 이해하지 못하면 기술적으로 동작하는 기능도 현장에서 사용할 수 없다.[^basis]

그래서 대표 메뉴의 처음부터 끝까지를 하나의 실증 시나리오로 실행하고, 기능 결과뿐 아니라 사용자 의견, 제한사항과 미해결 문제를 함께 기록한다. 장비나 데이터가 제공되지 않는 상황을 숨기지 않고 대체 검증과 한계로 남긴다.

## 실증 범위와 관찰 항목

- 대표 메뉴와 실증 범위를 정한다.
- 참가 역할과 수행 절차를 배정한다.
- 정상, 장애와 수동 입력 시나리오를 실행한다.
- 수집부터 평가까지 연결관계를 확인한다.
- 사용자 의견, 결함과 개선사항을 기록한다.
- 역할별 교육과 매뉴얼 제공 여부를 확인한다.
- 미해결 이슈와 제한사항을 남긴다.

## 검증 시나리오

1. 메뉴, 장비, 반복횟수와 평가방법을 승인한다.
2. [장비 도입환경과 활용 시나리오](equipment-adoption-scenario.md)를 실증 절차로 구체화한다.
3. Mock, 파일과 운영자 입력을 포함해 데이터를 수집한다.
4. AI 추천을 사람이 검토하고 조리작업을 수행한다.
5. 실제값, 결과와 품질평가를 기록한다.
6. 통과·실패·제한 결과와 사용자 의견을 정리한다.

## 실패와 책임 경계

- 실제 장비 미사용을 실제 현장 호환성 검증으로 표현하지 않는다.
- 실패나 미제공 데이터를 성공으로 간주하지 않는다.
- 장비 조작이 필요한 실증에서는 현장운영자만 실제 장비를 조작한다.
- 테스트 절차와 결과 증적은 별도 테스트 산출물에서 관리한다.
- 대표 메뉴는 정해졌지만 반복횟수·참가 역할·종합 합격 기준은 테스트 계획에서 확정한다.

## 설계 상태와 남은 작업

4단계 화면 흐름과 세 대표 메뉴·장비 조합은 확정 방향이다. 일곱 항목의 1~5점 조리품질 척도도 정해졌다. 메뉴·조리량별 세부 관찰 기준, 참가 역할, 반복횟수와 전체 합격 기준은 후속 화면 설계와 테스트 계획에서 정한다.[^validation]

Mock 실증에는 정상뿐 아니라 연결 단절, 재연결, 중복, 인증 실패와 인코딩 오류를 포함한다.

검증은 4단계 조리 화면 흐름과 수집·표준화·품질·AI 권고의 핵심 UML 흐름을 함께 통과해야 한다. Mock에서 5초 순번 결손과 정상·장애·수동 입력을 재현한다. 소스별 연결 상실·신선도 임계치와 메뉴별 반복횟수·합격 기준은 테스트 계획 전 결정한다.
