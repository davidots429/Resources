---
title: 조리계획과 진행·예외 관리
---

조리계획과 진행 관리는 메뉴, 승인 레시피, 사용할 장비, 단계와 순서를 하나의 조리작업으로 묶고 시작부터 완료·실패·중단까지의 상태를 기록하는 기능이다. 장비 데이터가 없는 단계는 운영자 입력으로 보완하되 출처를 표시한다.

여러 장비와 사람이 함께 조리하면 한 장비의 상태만으로 전체 진행상황을 알 수 없다. 권장값, 실제 적용값, 예외와 결과가 다른 기록에 흩어지면 실패 원인과 개선 효과도 연결하기 어렵다.[^basis]

그래서 조리작업을 공통 기준으로 삼고 모든 단계와 이벤트를 시간순으로 연결한다. 자동수집과 수기입력을 구분하는 이유는 데이터의 신뢰 수준과 누가 기록했는지 알 수 있게 하기 위해서다.

## 조리계획과 기록

- 메뉴, 레시피 버전, 매장과 장비로 조리작업을 만든다.
- 단계별 순서, 예상시간과 운영자 역할을 제공한다.
- 장비 수집 또는 운영자 입력으로 진행상태를 갱신한다.
- 중단, 재개, 실패와 예외 조치를 기록한다.
- 권장값, 실제값, 결과와 평가를 작업에 연결한다.
- 작업 타임라인과 현재상태를 보여준다.

## 작업의 진행

1. 승인된 레시피와 대상 장비를 선택해 작업을 계획한다.
2. 단계와 상태 전이 규칙을 초기화한다.
3. 장비 이벤트와 운영자 입력을 공통 상태로 변환한다.
4. 모든 상태 변화와 예외를 시간순으로 저장한다.
5. 완료 또는 실패 시 결과와 실제 설정값을 확정한다.
6. [구조화된 조리 품질 평가](cooking-quality-evaluation.md)로 작업을 전달한다.

## 실패와 책임 경계

- 잘못된 상태 전이는 거부하고 사유를 표시한다.
- 장비 상태가 없으면 운영자 입력을 허용하지만 자동수집처럼 표시하지 않는다.
- 플랫폼은 작업 상태를 관리하되 장비를 직접 시작·중단·재개하지 않는다.
- 승인되지 않은 레시피로 일반 조리작업을 만들지 않는다.
- 취소, 중단과 실패는 서로 다른 종료·일시 상태로 구분하며 메뉴별 복귀 조건은 PEND-013에서 확정한다.

## 설계 상태와 남은 작업

조리작업은 계획, 진행, 예외, 실제 설정값, 결과와 평가를 연결하는 중심 식별자다. 정상·중단·재개·실패 흐름을 모두 기록하고 입력 출처를 구분한다.

공통 상태 전이는 UML과 코드정의서에 반영됐다. 복수 장비 동시 단계, 메뉴별 취소·재개 조건과 역할별 실행 권한은 PEND-013과 화면 상세화에서 확정한다.

운영 화면은 `SCR-101 준비·예열 → SCR-102 투입·모니터링 → SCR-103 인양·평가 → SCR-104 AI 권고 검토` 순서로 설계한다. 작업 상태는 `PENDING ↔ READY → RUNNING ↔ PAUSED → COMPLETED/FAILED/CANCELED`을 사용하며, 평가 대기는 작업 상태에 섞지 않고 별도 판정으로 관리한다.
