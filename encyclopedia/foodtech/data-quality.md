## 한눈에 보기

데이터 품질 검증은 누락, 중복, 형식, 범위, 단위, 코드, 순서, 시각, 참조 관계와 상태 전이를 검사하는 기능이다. 오류를 단순 삭제하지 않고 사용할 수 있는 이상값과 사용할 수 없는 값을 구분하며, 원본과 보정값을 함께 보존한다.

## 왜 이렇게 정했는가

모든 이상값을 버리면 실제 현장의 중요한 변화를 놓칠 수 있고, 모든 값을 정상으로 받아들이면 분석과 AI 학습이 오염될 수 있다. 또한 통계적으로 드문 값과 물리적으로 불가능한 값은 처리 방식이 달라야 한다.

그래서 품질 판정을 `Warning`과 `Quarantine`의 두 단계로 나눈다. 재현 가능한 형식·단위 변환만 자동 보정하고, 결측치 추정이나 보간처럼 원래 값을 새로 만들어내는 처리는 자동 보정으로 인정하지 않는다.

## 무엇을 하는가

- 필수값, 형식, 단위와 코드 유효성을 검사한다.
- 중복 키와 순번을 이용해 중복과 결번을 찾는다.
- 시각의 선후관계와 참조 무결성을 확인한다.
- 통계적으로 이례적이지만 가능한 값은 `Warning`으로 표시한다.
- 물리적·논리적으로 불가능한 값은 `Quarantine`으로 격리한다.
- 자동 보정 전후 값과 적용 규칙을 함께 기록한다.
- 학습데이터 후보가 품질 기준을 충족하는지 판정한다.

## 어떻게 동작하는가

1. [데이터 표준화와 코드 매핑](data-standardization.md) 전후에 적용할 품질 규칙을 선택한다.
2. 필수값과 형식을 먼저 확인하고 중복·순번·시각 관계를 검사한다.
3. 범위 위반을 소프트 리미트와 하드 리미트로 나눈다.
4. 소프트 리미트 위반은 정상 파이프라인에 남기되 검토 대상으로 표시한다.
5. 하드 리미트 위반은 정상 처리에서 제외하고 별도 격리 영역에 보낸다.
6. 보정이 허용되면 원본을 유지한 채 보정값과 규칙 버전을 추가한다.

순번이 건너뛴 경우에는 즉시 누락으로 확정하지 않고 5초 동안 늦게 도착한 이벤트를 기다린다. 이 대기 시간을 둔 이유는 네트워크 순서 뒤섞임을 실제 데이터 손실로 잘못 판정하지 않기 위해서다.

## 예외와 경계

- 결측치 채우기, 통계적 추정, 보간과 모델 기반 대치는 자동 보정하지 않는다.
- 격리된 데이터는 정상 분석이나 학습에 사용하지 않는다.
- 경고 이력이 있는 데이터는 현재 값이 정상이어도 학습 후보에서 제외한다.
- 품질 규칙이 원천 데이터의 실제 의미를 바꾸어서는 안 된다.
- 구체적인 시험 절차와 증적은 테스트 산출물에서 관리한다.

## 현재 결정

자동 보정은 입력, 규칙과 출력을 재현하고 역산할 수 있는 경우만 허용한다. 학습 후보는 경고 이력이 없고 현재 품질 상태가 정상이며, 핵심 Feature와 Label에 Null이 없고 승인된 키로 중복 제거된 데이터만 통과한다.

데이터별 소프트·하드 리미트 수치, 신선도 기준, 늦게 도착한 이벤트의 재조정 방식과 격리 데이터의 보존·복귀 절차는 설계 단계에서 확정한다.
