## 한눈에 보기

웹 화면과 통합 현황판은 장비 데이터, 레시피, AI 추천, 승인, 조리작업, 평가, 분석과 운영 상태를 브라우저에서 사용하는 기능이다. 사용자의 역할과 매장 범위에 따라 메뉴와 데이터가 달라진다.

## 왜 이렇게 정했는가

현장운영자와 외식업주가 전문 데이터 도구를 사용하지 않고도 핵심 업무를 수행해야 한다. 동시에 수집이 중단된 오래된 값을 현재 상태처럼 보여주면 잘못된 판단을 만들 수 있다.

그래서 업무별 화면을 하나의 웹 인터페이스로 제공하고, 장비 값에는 최종 수신시각, 연결상태와 출처를 함께 표시한다. 직접 장비제어 화면을 두지 않는 이유는 이 플랫폼의 책임이 조회, 분석과 의사결정 지원에 한정되기 때문이다.

## 무엇을 하는가

- 통합 현황과 장비 연결상태를 보여준다.
- 레시피 생성, 검토, 승인과 제공 화면을 제공한다.
- 조리작업의 진행, 예외와 실제값을 입력·조회한다.
- 평가와 운영성과를 표와 그래프로 표시한다.
- 사용자, 권한, 매장과 운영설정을 관리한다.
- 장애, 지연과 재처리 상태를 보여준다.

## 어떻게 동작하는가

1. 사용자를 인증하고 역할별 메뉴를 구성한다.
2. 서버 API가 매장 범위와 작업 권한을 다시 확인한다.
3. 화면이 필요한 데이터를 조회한다.
4. 최신 수신시각, 데이터 출처와 지연상태를 함께 표시한다.
5. 입력·승인 작업은 결과와 오류를 명확히 보여준다.
6. 중요한 작업은 감사이력으로 남긴다.

## 예외와 경계

- 오래된 데이터를 현재값으로 표시하지 않는다.
- 클라이언트에서 숨긴 메뉴만으로 권한을 통제하지 않는다.
- 스마트폰 접근은 가능할 수 있지만 공식 지원을 보장하지 않는다.
- 장비 시작·중지·설정 전송을 위한 제어 UI를 제공하지 않는다.
- 외부 AI 요청은 일반 조회와 다른 대기·오류 표시를 사용한다.

## 현재 결정

Chrome, Edge와 Firefox를 공식 지원하고 Safari는 호환 목표로 둔다. x64 Windows, Ubuntu/Debian과 Fedora에서 검증하며 최소 화면은 1366×768이다. 4:3, 5:3과 16:10 화면비에서 핵심 기능을 사용할 수 있어야 한다.

화면 정보구조, 세부 반응형 구간, 동시 사용자 수와 화면별 성능 목표는 설계 단계에서 확정한다. 일반 대시보드 조회의 초기 목표는 p95 2초 이내다.
